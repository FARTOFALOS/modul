# modul — модуль агентской торговли

Панель защиты MNQ для NinjaTrader8, перенос индикаторов TradingView и спецификация стека DR Lab23.5 → NinjaTrader → Rithmic. Рабочий режим оператора: **торговые действия через экран, только Sim101 для агентских проверок**.

Исправление `v11.06-S300-F1`: защитный стоп удаляется и когда подтверждённое исполнение выхода приходит раньше обновления позиции Flat. Существующие запреты повторной отмены исполненного ордера сохранены. Пройдены5258 вычислительных/lifecycle-проверок и перечисленные экранные сценарии — [точная матрица проверки](docs/VALIDATION.md). Остальные сценарии явно NOT_TESTED; глобальной сертификации нет.

## Состав

`src/ninjatrader` — панель, арифметика/lifecycle, существующий ограниченный Sim101 API v1. `src/tv-port` — индикаторы, без исполнения. `integrations/dr-lab` — пассивный сборщик и женская озвучка DR-активаций для отдельного проекта DR Lab. `config` — обезличенные настройки защиты и индикаторов. Историческая база и сам аналитический движок DR Lab сюда не перенесены.

## Сборка и установка

Windows x64, .NET Framework4.8, собственная установка NinjaTrader (проверено8.1.8.4).

```powershell
./tools/test.ps1   # чистые тесты, без терминала и сделок
./build.ps1        # полный локальный native build, не меняет установленную программу
./install.ps1      # только при закрытом NinjaTrader, с проверкой хэшей и backup
```

Сборка `.local/build/NinjaTrader.Custom.dll` содержит также исходники/ресурсы собственной установки терминала и остаётся **локальной**. Публичный dist — пакет наших исходников и сборочных инструментов. Библиотеки NinjaTrader/вендоров, пароли, счета, конфигурация подключений, лента и журналы не публикуются.

На чистом Sim101-графике выбрать MNQ DEC26 и добавить MNQProtectionPanel с `config/sim101.json`. Этот JSON описывает параметры, сам не настраивает терминал. Риск300/комиссия2 относятся к MNQ; перенос на YM/IB требует отдельных tick/point/fee параметров. Ни индикатор, ни сам repo не создаёт сигнал входа из процентов23.5.

## Дальнейшие изменения

Изменения оформляются отдельными PR с воспроизведением дефекта, проверками и отметкой фактически установленной версии. Новую ошибку сначала зафиксировать; исправление не объявлять проверенным до повторения нужного сценария. Не расширять API на реальные счета. Существующий API v1 не реализует BE/change/limit/add/partial-close; его тестовый скрипт требует отдельного явного `--execute-sim` и нового разрешения человека. Текущий операторский запрет на торговлю API имеет приоритет над наличием этого скрипта.
